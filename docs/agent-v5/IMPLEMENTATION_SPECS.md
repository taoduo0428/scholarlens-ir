# E13–E16 实施与发布规格

负责人为项目组长。下列四项属于待实现范围。先按 E10 指南锁定人工评审题，再按对应成功条件决定是否上线。

## E13 检索、版面和综述

当前入口是 `backend/retrieval.py`、`backend/research/tools/registry.py`、`backend/research/overview.py`。现有离线评测可运行 `python -m tools.research_eval.v5_compare --output output/new-holdout`。按真实论文组统计综述发布率，另外从人工标签计算支持率。6 组真实摘要在独立集内均缺少跨论文可追溯的完整综述。这一组适合定位损失。下一次验收要另选未开启的论文组。

| 工作项 | 实施位置与输入输出 | 验收与关闭方式 |
|---|---|---|
| 混合召回、拆题与扩词 | 从节点证据需求生成原始查询、扩展词及关键词/向量结果。使用相同许可范围做 RRF。逐级保留排名、原查询和策略版本 | 在同一组人工 qrels 上分别移除扩词、向量、分解。报告 recall@10、nDCG@10、工具数、p95 和区间。任一范围错误即关闭实验策略 |
| Cross-Encoder 重排 | 在召回后只重排许可候选，向工作台返回排序依据、模型摘要、批次耗时 | 相同 top-k 和相同语料下验证排名质量。延迟超过既有交互预算时回退 RRF。模型拉取和价格单独审批 |
| 引用图与多跳 | 存储 DOI/稳定论文 ID、引用边和原文指针。沿有来源支持的边添加候选，逐跳重新检查权限及来源版本 | 缺边、同名不同论文、循环、跨权限引用各有夹具。最终命题保留完整前提链，最大深度和工具限额沿用任务预算 |
| PDF、OCR、表格与插图 | 先对授权 PDF 验 SHA，版本化保存页索引、坐标系、边框、文字和置信度。表格保留表头及单元格，图保留图注、位置和数据来源 | 抽样人工复定位坐标和字符。扫描页、旋转页、跨页表格、缺失原件分别测试。适配器关闭时返回来源能力不足 |
| 跨论文综述、系统性综述和趋势 | 从各论文方法、终点、样本和条件构建对照，另存纳排标准、检索式、去重记录、筛选决定。将作者提出的空白与系统推断分别引用 | 由两位评审判断跨文献可比性、趋势、冲突和研究空白。展示缺失论文和反例。研究结论发布仍走服务器门禁 |

## E14 记忆与技能治理

现有上下文组装见 `backend/research/context_layers.py`，已批准策略只读加载见 `backend/research/skills/registry.py`。第一阶段可在实验库新增 `memory_candidate(id, owner, project, kind, source_version, source_locator, content_hash, expires_at, supersedes, review_status)`。即时执行经历、语义事实、程序技能和项目决定四类各自限定可见范围和保留时间。写入前检索同一来源版本及内容摘要。跨项目复用需要显式授权。

合并同义条目要保留每条出处，矛盾版本并列待评审。来源撤销、权限收缩或到期后停止检索该条目。用户删除后同时清理嵌入索引并保留最小审计回执。发布顺序为执行记录、技能候选、固定预算离线对照、历史回归、人工批准、不可变版本发布。失败时继续使用上个已批准版本。验收应覆盖旧任务按原策略恢复、冲突信息、用户隔离、来源撤销、过期和来自文献的指令文本。人类标签补足前，只允许实验库生成候选。

## E15 协作角色与试验门槛

保留单 Agent/LangGraph 作为基线。候选实验以一个复杂跨论文任务为单位，共享同一模型/时间/工具总额。Supervisor 分配子预算，实际用量在同一任务账本扣除。子任务携带所有者、任务 ID、许可论文/动作集合、剩余预算、到期时间和唯一调用编号。服务端取父授权与委托范围的交集。MCP 仅暴露只读检索和回读，A2A 试验只传结构化命题引用，子任务结束时清除上下文。

| 角色 | 输入和产物 | 权限与建议起始预算（整题 10 次工具） |
|---|---|---|
| Supervisor | DAG 和剩余预算，拆成单论文任务 | 协调，0 次。禁止自行授予范围 |
| Research Worker | 许可论文及字段，返回候选段落 | 研究检索合计 4 次 |
| Evidence Reviewer | 候选段落、原文版本，返回核验记录 | 原文回读 2 次 |
| Methodology Analyst | 已核验的数据集、条件和指标，返回可比性说明 | 检索或回读 1 次 |
| Synthesis Agent | 已核验命题和反例，返回带前提的综述草案 | 只读内存，0 次 |
| Independent Verifier | 草案、引用和许可范围，向服务端返回可发布字段 | 独立回读 3 次，禁止写正文或修改门禁 |

每个委托加 trace 父标识并验证重复投递、串任务、父任务取消、超时和引用过期。只有在新的成对人工任务上成功率改善、错误发布未上升、整题预算未增长时再讨论上线。可先在现有图中实现独立复核节点完成相同对照，再决定是否值得引入跨进程协议。

## E16 产品、协作与发布

现有页面覆盖账户、论文、检索、书架、研究工作台、助手模型配置、管理后台，工作台含 DAG、字段矩阵、证据与报告。Evolution Lab 按前端开关和后端管理员权限开启。Playwright 已覆盖本地任务恢复、跨账号隐藏任务及三种窗口宽度。跨任务费用统计、面向用户的工具权限管理、知识有效期界面及独立公开发布流程仍待验收。

1. 产品负责人以普通用户、管理员各走一次注册、登录、研究、报告、任务历史、模型设置和知识来源撤销流程。费用页面要能区分执行次数、实测 Token 和未知价格。工具管理只能收缩服务端允许的权限。账号隔离在 API 层验证。
2. 运维先以临时 SQLite 库验证 schema 初始化、快照恢复和任务级隔离，再复跑相同工作台任务。现有 `infra/elasticsearch.compose.yml` 只编排 ES。后续增加 API 和前端构建容器，使用独立卷、最小权限、秘密注入和就绪检查。准备旧镜像、兼容数据库快照以及配置后，在预发布演练回滚。当前环境未进行生产演练。
3. `infra/ci/verify.yml` 是 CI 模板。将其装入 GitHub 实际识别的工作流位置前，在隔离分支验证仓库权限、系统矩阵、锁文件、密钥扫描和 PR 基础分支。模板的存在不构成远端 CI 成功记录。公开发布前补维护者、安全报告渠道、用户手册、贡献说明、迁移影响、版本标签与发布变更记录。
4. 单独准备 `main` 整合 PR。先对 `main` 独有正式 JSONL、来源清单和 LFS 指针做对象哈希、行数、论文 ID、重复率与来源差异表，在新目录生成独立索引，同题比对后由数据负责人审阅。保存两条分支指针，再决定合入方向。现阶段使用 `zjl` 作为集成分支。
