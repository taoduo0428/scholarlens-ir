# 任务运行与恢复

在同一 SQLite 队列和一个工作进程上，分别同时提交 1、4、12 个账号的任务，核验重复提交键、完成状态、跨账号访问和备份恢复。每次试验使用独立临时目录。详情见 `tools/research_eval/v7_runtime.py` 和提交 `1cd1dfe`。

|并发用户|完成|p50 秒|p95 秒|恢复后报告哈希符合|
|---:|---:|---:|---:|---:|
|1|1/1|0.375|0.375|1/1|
|4|4/4|0.625|1.343|4/4|
|12|12/12|2.500|4.922|12/12|

命令为 `python -m tools.research_eval.v7_runtime --output <results.json>`。输入是本地受控论文，17 个任务均为零模型调用。该试验覆盖用户并发和 SQLite 恢复，长任务、外部供应方限流、跨进程分布式恢复和高负载写入仍需单独测量。当前部署按单 worker 配置。

HTTP 存活探针为 `GET /healthz`，就绪探针为 `GET /readyz`。服务只在指定索引的导入元数据和 SQLite 用户表均可读时报告 ready。已测就绪、别名缺失、搜索离线和 SQLite 故障。失败响应为 503，存活探针仍可返回 200。该处不探测模型服务和向量模型。
