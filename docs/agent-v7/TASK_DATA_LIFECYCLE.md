# 研究任务的导出和保留

研究后端维护者负责以下接口。登录用户可以下载自己任务的 ZIP，包含同一修订的状态、事件、已绑定的证据与已发布报告。清单给出各文件的字节数和 SHA-256。产物无法通过原哈希核对时，接口返回 409。

在工作台任务详情中，「导出任务 ZIP」使用当前登录会话下载压缩包。已结束的任务显示「删除任务」，用户可先导出，再确认永久删除或保留任务。确认提交时使用打开确认提示时的修订号。服务确认删除后，页面返回任务列表；请求失败时显示原因并保留详情。

2026-11-22 在本机 Chrome 157.0.8103.79 的两种前端构建中验证了同一流程。用户实际下载的 ZIP 均可打开，清单中的 7 个文件逐一通过字节数与 SHA-256 校验。点「保留任务」后仍可访问，提交过期修订号返回 409 并显示原因。确认删除返回 204，工作台随即返回任务列表，原详情和导出接口均返回 404。切换账号后，其他用户的任务仍可正常访问。复验命令见[工作台任务追踪](TRACE_VIEWER.md)。

用户可按任务 ID 和最后看到的修订号删除一项已结束的研究任务。服务同时清理该任务的图执行记录、研究证据、报告、项目记忆和用量回执。活跃任务或已变化的修订返回 409。所有权校验失败返回 404。独立运维备份、外部追踪收集端和导出到用户设备的文件各自按保存方的保留策略处理。

运维可针对指定账号和 UTC 截止时间预览到期的终态任务，再凭预览摘要执行同一批清理。服务默认保留任务。验收使用两个临时账号和独立数据库，核对导出清单、旧修订、跨账号访问、图执行记录以及失败重试。

### 接口

- `GET /api/research/tasks/{id}/export` 下载 ZIP。解压后按 `manifest.json` 核对文件哈希。每个快照最多包含 2,000 个事件、8 MiB 的状态和产物数据。超限时可通过原事件分页和单项产物接口分别读取。
- `DELETE /api/research/tasks/{id}?revision=4` 删除指定修订的终态任务，成功返回 204。再次查询返回 404。成功前会先清理图执行库中的对应线程，再提交主库事务。存储故障时可重试。恢复历史备份后需重新应用其备份时间之后的删除决定。

### 运维保留策略

运行 `python -m tools.research_retention --runtime PATH --owner 7 --before 2026-01-01T00:00:00Z` 查看本批数量和摘要。先备份数据库、暂停该运行目录的研究 Worker，再以相同参数和 `--confirm 预览摘要` 清理。每批默认 50 项，最大 100 项。下一批重新预览。该操作仅针对研究任务，账号及共享论文资产沿用各自的管理流程。
