# ScholarLens E11–E17 研发协议

基线为 9610dac，开发分支为 codex/evo-full-product，负责人为项目维护者。输入包括用户研究目标、已授权来源、持久化任务、实验预算。输出包括按论文与问题归属的证据档案、综合报告、运行轨迹、权限边界及本轮可复现实验。

## 研究质量验收

冻结语料使用既有 LFS SHA-256。用固定盐排序，排除旧基准及 V2–V6 报告提及的所有论文，选择 24 个论文对和 4 个三篇组。开发阶段只使用既有诊断语料和合成回归。各策略使用相同论文、相同问题、10 次工具预算和零模型预算；真实供应方另测。双篇综合仍使用 V5 的双来源前提指标。旁列描述、共同研究条件、趋势和因果分别统计。原句题要求与目标论文一致，缺失布局题检查误发。比例报告分子、分母和 Wilson 区间。开放语义的准确率须标明判断来源。111 题沿用已冻结的 AI Silver。

## 综述的证据要求

E11 的逐篇观察可独立发布，保留每条作者原句和来源。跨篇关系字段需要一条覆盖所请求论文的关系，每篇均有同一关系所需的原句。相同方法要求作者明确采用可核对的同名技术。不同方法要求原文同时给出相同用途和各自使用的技术。方法关系依赖对应的方法证据。结果和局限的缺口在各自字段展示。仅有相同变化方向时，性能和因果判断仍缺少依据。

验收使用合成正反例和同组论文的前后回放。分别统计逐篇直接回答、完整逐篇方法和结果、全组关系及来源覆盖。保留冻结的 V5 判据及原结果。

## 产品接口与验收

单工作进程的恢复验收使用独立 SQLite 库和合成摘要，由维护者运行。主进程发现已有证据的持久检查点后，启动第二个进程竞争同一执行锁。主执行进程意外退出后，接替进程须保留同一任务、原有证据和账号隔离，并生成一份可核对哈希的报告。

维护者通过 `SCHOLARLENS_IMAGE` 指定已构建的应用镜像。容器验收使用独立的 Compose 项目和测试卷，依次检查空索引、就绪探针、账号、研究数据库备份恢复和回退到上一镜像后的数据可读性。

研究工作台按用户指定的论文及其原文分别核对作者的研究目标、问题和方法。维护者负责问题规划与发布核验。指定论文的事实可以单独作答，跨篇因果关系需要独立的关系证据。单篇简报中的额外要求沿用原有字段类型和验收条件。验收覆盖显式否定、追加指标、多个明确目标、同名论文、范围内的干扰论文、缺少跨篇依据与前人研究归属。

研究分析以独立策略 E11 接入现有图执行器。结构化候选携带论文、证据 ID 和精确原文区间。服务按用户、语料版本、证据哈希、原句完整性和语义角色复核。每个问题计划列明必要字段、可选字段和接受条件，关系报告保留双方来源和首个缺证环节。项目记忆以用户和项目复合键保存已核证的内容。

PDF 页级接口返回同页图像和编号题注的版面关联。每项保留图像区域、题注原行和双方位置。只有相邻、水平重叠且双方唯一时才建立候选关联。由维护者使用出版社 JATS 题名及独立发布的位图验收，并报告多列、歧义区域和装饰图的处理结果。

PDF、表格、公式和图像以文档哈希、页和区域为证据位置。工具网关按服务端身份验证访问。恢复、并发、窗口隔离、发布审批、备份及恢复需通过实际操作验证。前端使用任务 API 展示报告和花费。所有发布判断以最终代码、实际测试和各项外部依赖的运行结果为依据。

运维探针由后端维护。GET /healthz 在应用能处理请求时返回 200。GET /readyz 要求论文索引映射和 SQLite 用户表均可读，依赖故障返回 503，响应只含状态。出版社 JATS 表格作为独立于 PDF 读取器的行列核对来源。只有表头、行和数值映射可重现时才计入结构化表格命中。

研究模型网关复用个人请求已验证的协议和端点配置。服务端同一进程最多同时执行四次研究模型请求，同一端点最多两次。容量耗尽立即返回已有的限流状态。匿名信息仅含协议能力，不含账号配置、模型密钥和端点。已审批技能在绑定时核对配置摘要、评审摘要和同版本审批记录。验收包含并发上限、异常后容量恢复和审批记录不一致。
启用 OpenTelemetry 时，服务在创建任务的同一笔事务内保存服务端 API span 的跟踪标识。后台执行从该标识继续，建库时为旧任务库增加独立关联表。验收核对首个 API span、工作进程、检索、核验、综合和发布的父子关系及账号归属。关闭追踪的任务按原方式运行。追踪属性只记录阶段、结果和错误类别。

研究网关由后端维护。使用同一本地容量目录的进程共享四个在途请求名额，同一主机最多两个。配置由部署端提供，能力接口返回限额适用范围。容量已满或运行卷不可用时，调用方收到现有的限流结果。验收在独立进程中统计同时到达受控 HTTP 接收端的请求，并检验进程终止后的容量恢复。

项目看板按登录用户、工作区和项目选取最近 50 项任务，统计状态、已计量用量、费用估计和完成耗时。缺费用的任务单列。每个任务可以查看已记录的追踪 ID。

研究后端负责将描述性问题中的方法名称、适用场景和紧随其后的代词绑定到相应字段。用户可以分别询问该方法解决的问题、使用的输入，并要求补充其他证据。每个已答字段应引用授权来源中明确表述该对象和关系的完整原句。验收逐项核对引用、场景、对象和遗漏的字段，并在冻结题上记录新旧策略的直接回答和误发。

研究任务可以指定一个 PDF 单元格作为补充证据。请求必须同时提供论文 ID、PDF SHA-256、页、页内表号、物理行与列。服务核对账号和任务范围，计入工具预算，按文档版本读取原单元格，在报告及 Markdown 中保留值和位置。缺失、文档版本变动或预算耗尽时，报告保留具体原因。
