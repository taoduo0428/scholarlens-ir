# P3 单 Agent 自适应执行

`backend/research/graph.py` 用 LangGraph 驱动计划、发现与读取、覆盖检查、补检和报告节点。`planner.py` 根据问题中的方法、数据集、指标和实验条件生成子任务。`worker.py` 从本地数据库领取任务并实际确认暂停和取消。`api.py` 将任务绑定到当前用户。`context.py` 只把有限查询历史、证据引用和槽位交给决策器。`provider_adapter.py` 复用已有 BYOK 协议解析、外联传输与请求隔离。

真实运行的缺口 fixture 在第一轮读到 Atlas 的方法，第二轮改写查询后找到另一篇的指标。首轮完成后中断再恢复，已记录的证据和调用序号均保留。空语料两轮后以 plateau 结束。超时、429、无效模型动作、语料代变化、凭据遗失和并发控制均有回归。正常 App 关闭功能时不会建立研究库。

在 worktree 根目录执行 `.venv/Scripts/python -m pytest backend/tests/research/test_execution.py backend/tests/research/test_service_boundaries.py -q --basetemp .venv/root-boundaries-2`，退出 0，14 项通过。测试使用受控 provider 和工作区 SQLite。单 Worker 的真实本机容量数据见 P8。P4 接收已通过原文回读的 evidence 引用，发布时再做逐结论核验。[命令输出](../evidence/p3/worker-and-boundaries.txt)

多篇范围任务以用户给定的论文清单为输入。研究后端应优先补查缺少已核验来源的论文，直至每篇都有证据、连续两轮没有新证据或达到硬预算。报告列出仍然缺少已核验证据的论文编号。

初次回归的六项用例均复现了范围内缺篇问题。修复后的七项用例分别覆盖了次轮定向检索、一篇缺失、原文不含所问方法、首轮无全库命中及三种 BYOK 动作。它们与既有执行和服务边界用例一起运行，21 项通过。项目以本地逐篇读取和原文核验判断覆盖情况。在部分报告中可以查看具体缺少证据的论文编号。[初次结果](../evidence/p3/scope-before.txt) · [修复后](../evidence/p3/scope-after.txt)
