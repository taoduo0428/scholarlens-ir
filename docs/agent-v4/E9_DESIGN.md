# E9 答案字段与发布契约

## 范围和验收协议

本轮交付总规格第十四节 A–E。集成基线为 fork 的 `zjl`，复用本地已验收的 V4 工作台与同一份研究 Runtime。E9 使用独立策略名和开关。研究账户仍通过任务 API 建立范围，外部输入只能提出问题。

对照使用相同公开摘要、问题、证据与工具预算、零模型配置。预注册程序 `tools/research_eval/e9_accept.py` 通过固定哈希选择 6 篇未用于 V3、种子、Review 或 V4 的论文。每篇运行首句、PDF 坐标和两字段题。另有 3 组主体与干扰对象相近的夹具。门槛为全答题精确原文命中不少于 V1 和 V5 中的较高者，缺失题发布次数更少，复合题保留已支持的部分并指出另一个字段的缺口，权限越界数为零。样本用于确定性工程验收。开放问题质量留给 E10 独立人工复核。

## 执行链

1. 服务端从用户请求和已校验的 Question DAG 生成 `AnswerRequirement`。每个 `AnswerField` 有唯一标识、所求属性、类型、来源能力、最小证据及论文数、实验前提和失败处理。字段定义随任务持久化，恢复时校验原绑定。
2. `SourceCapability` 按已回读字段和 locator 推导。摘要及正文可支持明确写出的数值，版面字段需要已核验的独立版面定位。现有字符偏移继续用于引用。PDF 文件可用标记不能授予坐标或页码能力。
3. 检索时记下哪一个问题读取了每条证据。生成和复核命题时按当前问题及其 DAG 依赖取证。同一段文字可以含不同事实，每个字段必须有自己的关系和可核查的值。跨论文比较核对题目范围、指标、单位、语料、协议和设置。
4. Critic 分别记录字段、问题和整题的可答性，再用缺口驱动后续读取。空结果记录检索覆盖范围。没有封闭清单及完整扫描的任务不能断言资料不存在。模型输出沿用已有的受控审核与用量预算，最终发布由服务端重查。
5. 发布器重新取得账户许可的原文，检查语料代次、内容摘要、字符区间、命题蕴含和字段关系。只有已满足字段进入核验区。复合问题可以发布部分原文结论，同时列出冲突、条件差异、来源能力限制和尚未解决的问题。API 和 Markdown 从同一份判断生成。
