# 缺证补查

E、G 的公共论文补查可以跳过相邻轮次中同一子问题已读完的相同检索。指纹包括语料版本、子问题和实际检索参数。只有此次返回的所有片段均由当前子问题读过并核验时才保存指纹。发布阶段仍独立回读来源。验收比较每题的已发布陈述、字段状态及实际工具调用次数。

实验 E 在 `backend/research/pra_gaps.py` 中根据每个字段的判定、已查论文、已有证据和节点依赖构建缺口。优先级按能否执行、缺失论文和受影响的下游节点排序。记录位于每个研究轮次的 `gaps` 和 `resolved_field_ids` 中。优先级是规则顺序，当前没有经过校准的解决概率。

第一版对所有缺口改写查询。111 题中工具调用从 994 升到 1,059 次，回答题数仍是 15。逐题记录显示，缺少归属时，换问法常常再次找到背景材料。修订版只对明确缺论文、方法、结果或条件的缺口调整检索目标，工具调用回到 994 次，单独启用时仍是 15 道。预算和来源能力边界沿用 LangGraph 原有执行约束。

现有方法与结果动作通过授权文本检索执行。缺少可用的版面能力时，字段保留缺证状态。最终版本复跑 E、G 各 111 道题。两组各跳过 4 次已经读完的重复检索，涉及 2 道题。相对 A，检索调用由 294 降至 290，总工具调用由 994 降至 990。700 次取证和发布回读全部执行。每题的字段判定、绑定的 Claim ID 和直接答案与优化前一致。
